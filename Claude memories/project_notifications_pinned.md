USER'S DESIGN (final, 2026-07-23 — supersedes my beacon sketch; do not build until fleet sync + message recovery are tested and the braid-in bug is fixed):
- Per-message **unnotified** flag on the rārangi row, synced fleet-internally like `delivered` (fleet-key-sealed; friends NEVER see it). Explicitly NOT "unread" — notification state records the fleet discharging its alert duty once, never whether the human read (read-state-as-data sidestepped entirely; privacy concern deferred by construction).
- **One active-clearer fleet-wide**: the most recent focus-gain/instance-open event wins the role (a new instance's claim DISPLACES the previous device even if its window still sits OS-focused). Claim scoped to the conversation whose screen is open. Claim refreshed by interaction events (click/keystroke), retracted by focus-loss/screen-off events, voided by presence loss (existing sibling ping machinery — covers crash/sleep without timers).
- On friend-message receipt: if the active-clearer has THAT convo open + screen on → it clears the flag, broadcasts to the fleet, NOTHING dings anywhere. Otherwise → normal notify path; exactly one device dings, flips notified=true, broadcasts (true-wins, idempotent). Siblings decide locally against the already-known claim — no waiting on the clear broadcast, no race timer.
- Catch-up: a backfilling device sees notified rows → silent (kills wake-from-doze ding-storms); a batch nobody flagged (fleet was offline) → one summary ding, then flag.
- ~~**Accepted quirk (user-stated)**: convo screen left open + screen on + human absent = that friend is silent all night, fleet-wide.~~ SUPERSEDED 2026-08-18 by the FLEET-ATTENTION layer (Nick: "we pass the ball around and if I close or navigate away from her messages, we drop the ball so all devices ding... no timers unless they are proven necessary").
- Implementation merge-point: the ding decision moves POST-decrypt (rows exist there; probes/system already filtered) — same relocation that fixes the everything-dings bug (status.rs ~2027 RX-worker pre-decrypt ding becomes the cold-FCM-only fallback). Android: full Rust app lives in the foreground service, so post-decrypt logic is available with the Activity dead.
- Transport symmetry: friend's fleet already reply-TXes to the last-RX'd device — the notifier/clearer is naturally the device the conversation is concentrated at.

**FLEET-ATTENTION LAYER (the ball) BUILT 2026-08-18, same-day follow-up**: `fleet_attention` = (device, osc) — the device with the human's NEWEST INPUT, LWW by eagle osc + device-byte tie-break, Lamport-bumped at every sender (max(now, seen+1): local input beats any clock skew; claims bumped identically). Frames only on the TRANSITION edge (non-holder gets a press/wheel/key/IME — zero frames while typing; CursorMoved excluded as bump-prone). Focus-gain and Android resume count as input (alt-tab/unlock deliver no press). A claim IS attention (one frame moves both slots — kills the attn/claim reorder race). BOTH ding gates require holding attention: looking = open && attended && attention_is_ours && FRESH; claimed_elsewhere additionally requires claim.device == attention holder. FRESH = last_interaction within 120s, checked ONLY at the message-arrival edge (Nick-approved sole time constant — the walk-away gap has NO input edge anywhere; the arriving message is the clock). Stale holder retracts its claim AT that edge (frame built directly for the token, NOT via broadcast_focus_claim which derives from the open view). Drop-sweep (factored catch-up chirp, bounded by claim osc) fires on: retraction receipt, presence-void of holder, attn displacing the claim holder — covers every crossing race. Presence-void clears attention too. Sibling link-up re-announces STORED oscs (never minted fresh — an abandoned reconnector must LOSE the LWW, not yank the ball back). Desktop banner gate = attended && ATTENTION_OURS atomic (mirrored in set_fleet_attention, the single mutation point). Android pause/resume latched as edge flags in nativeSetForeground, drained in tick → on_focus_changed(current truth); safe-lazy because the wrongly-suppressed message is the traffic that wakes the tick, and the sweep covers the flight window. Design adversarially case-checked (16 cases in ~/.claude/plans/pure-forging-acorn.md). Field verify: mac roster-click while Android parked on Emma's convo → ALL devices ding incl. the Android; walk away 2min → stale retract + fleet ding; background Android on convo → phone AND siblings ding.
