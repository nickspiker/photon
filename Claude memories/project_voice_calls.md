**Voice calls v1 — the first major AFTER the fleet cutover closed.** Built 2026-08-18 across 6 commits (abcf540 audio substrate → 2b64d28 keys → 1e3db92 wire → cc7b509 state machine/UI → 48cd2b8 media engine → 72a95d4 recording). All in `src/call/` + `src/platform/audio.rs` + `src/ui/photon_app/call_ui.rs`. `docs/calls.md` is the concrete design; this is the pointer + the load-bearing decisions.

**The through-line (Nick's framing):** calls fall out of the architecture. Three planes — SIGNALING rides the friendship lanes as encrypted control rows (`CALL_PREFIX`, the probe/delete/attach convention: a call is wire-indistinguishable from a text, inherits fold trust + receive-anywhere + retransmit); MEDIA is an ephemeral UDP plane (one non-VSF datagram, magic `C7 11`, recv fast-path BEFORE the parse ladder, no PT ack); HISTORY is ordinary summary rows + optional kept-recording blob.

**Keys = the DOZEN-EGG basket, no lone ECDH** (Nick: "I don't ship one eggs, I ship a whole dozen" — a single X25519 would be the ONLY quantum-soft link in an otherwise symmetric/hash system). `call_secret = KDF(lane_root ‖ history_key ‖ lane_key@offer_position ‖ call_id ‖ caller_nonce ‖ callee_nonce)`. The offer's lane key is DOOMED material (ratchet destroys it → per-call FS); caller captures at send-commit (content-matched), callee at decrypt pre-advance. Intra-call ratchet steps every 100 PACKETS (count, never a timer), zeroizing old steps; teardown drops both StepChains → call cryptographically gone. KAT frozen from an independent blake3 computation.

**Codec (2026-08-19 rework):** Opus RESTRICTED_LOWDELAY (CELT, 2.5ms, NO voip mode / in-band FEC) on a CHANNEL-AWARE CBR LADDER — 16/32/64/128 kbps rungs, every call starts at the floor and climbs on receive-side cleanliness (~1s clean = +1 rung), drops 2 rungs on a lost window (AIMD, edges not timers). Slots/windows are TIER-SIZED (fixed max-size slots would pad 16k to 128k's wire cost — the padding trap); each packet carries its window's tier byte so the receiver derives slot walk + OTI per window. CHANNEL-driven only, never content-driven: VBR is PERMANENTLY off the table (packet-size side channel = phrase-spotting on encrypted VoIP); within a rung the wire is constant CBR. RaptorQ 2-frame windows (~10ms batching). No PLC — a lost window is silence. Egress from the MAIN socket via a dedicated tokio forwarder; address-follows-auth. Climb evidence is a PROXY (local RX cleanliness) until a call_stats feedback frame exists. Deps: `opus` + `raptorq` + `cpal`.

**Latency (2026-08-19, measured not guessed):** was ~80-120ms one-way; the whole Android chunk was the VOICE_COMMUNICATION voice pipeline (granted=80ms buffer, never fast-mixer — measured via the render-up log). Output moved to USAGE_MEDIA + PERFORMANCE_MODE_LOW_LATENCY with a native-burst-sized buffer (vendor AEC traded away — Nick's call); capture stays VOICE_COMMUNICATION. Engine poll 1ms; adaptive jitter buffer in platform::audio (prime-to-target, underrun grows, clean shrinks to a 20ms floor, resets per call). Engine-down logs: rx tally (seen/parse/route/open/decoded — addressing vs secret-desync), audio level (tx-mic vs rx-play, placed one-way-heard at capture vs playback), ladder trace, duck count; Android logs granted buffer + lowLatency flag + underruns.

**Ring/answer = the attention machinery inverted:** ring BYPASSES claim/attention suppression (a call is the one always-ring event); answering is taking-the-ball (first wins, losers get Taken); NO ring timer (caller's patience IS the timeout, unanswered hangup mints the missed row). RING REQUIRES DIRECT DECRYPT — merge-path signals only STOP rings, which also kills the stale-offer-rings-days-later class. Summary rows stamped offer_osc+1 (shared across both fleets → merge-folds). See [[project-notifications-pinned]] for the attention/claim layer this reuses.

**Recording by DEFAULT** (Nick — dislikes services that deny later note-taking): endpoint memory, NOT wire retention. Engine spools already-ENCODED frames both directions (~25MB/hr) sealed under a random per-call spool key in the SpoolTicket. Hangup → Ended phase, Keep/Delete bar. Delete = drop ticket (key zeroizes, file is garbage — instant shred; crash-before-decision == delete). Keep = decrypt once into a SEGMENT-STRUCTURED VSF container (eagle-stamped `[dir|osc|len|opus]` — notes/transcription later = annotation layers; handoff = multi-segment) → content-addressed blob + fleet-internal attachment row (sibling push, NEVER chain-transmitted; friend's fleet keeps its own). §14.8 doctrine on media: destruction = key death.

**Echo** (the acknowledged-hard part, physics not architecture): layered — (0) headset route = bypass, (1) capture-side Android VOICE_COMMUNICATION source (mic-side vendor processing; output-side vendor AEC GONE with the MEDIA-path switch), (2) SOFT ENERGY DUCK BUILT 2026-08-19 in the engine TX loop: far_level() (peak-held render level, ~80ms decay, in platform::audio) over DUCK_FAR_LEVEL → mic glides to 0.1 gain (fast attack ~2 frames, slow release ~200ms), headset route bypasses, Android route() still returns Unknown (= ducks, safe default) until Kotlin wires route callbacks, (3) own canceller only if field demands. Duck constants are field-tuning knobs; the engine-down log counts ducked frames. tx-level in the tally is PRE-duck so a heavy duck never reads as a dead mic.
