Nick 2026-11-08: every FGTW app (Photon, Mahere, Lumis first) checks for an identity on the device; if none, it runs the shared fgtw attest, and then every app sees it ("1 means 1"). On ferros the OS attests. A device with no identity shows "This device is unbound: tap to attest". One About page across the apps doubles as the dashboard (attached apps with grants + Detach, Discover). "No store. Open." — Discover is a signed pointer list; trust is the developer's capsule signature.

Canonical: photon docs/one-identity.md (states Unbound/Locked/Live, what moves out of Photon, the `kists` record from ferros docs/KISTS.md riding fleet state, open decisions, build order) and tohu docs/oracle-hardening.md "Beyond the oracle" (tag + kernel).

**Facts that shaped it:** desktop apps already share one session (tohu `$XDG_RUNTIME_DIR/tohu`); Android sessions are per app, but same-signer apps share ANDROID_ID, so they are one fleet device and attest resolves Member — only the session needs a same-signer channel. Mahere uses tohu only via kete; Lumis is Kotlin UI with no identity.

**Trust hardening (Nick wants both built and noted):** plate sources are readable by any process. A crypto tag as PIPE: FIDO2 `hmac-secret` is the fit (32 B salt in, 32 B out, deterministic, secret never leaves, NFC on phones and USB on desktops, salt = keyed BLAKE3 of handle_proof for per-handle separation). NTAG 424 DNA (Nick's "4xxx") is the wrong shape: symmetric AES means the checker holds the key, and its SUN MAC is counter-bound so nothing repeats. The tag joins the KEY half above frozen v0 (gates fleet signing key or vault unlock), never the plate. Kernel "software PIPE": Linux feasible (SELinux/AppArmor first, LSM later), Android only on flashed kernels, Windows heavy, macOS not viable. Recommended: tag first.

**Why:** Nick's direction for identity across the app family plus the security audit's device-root exposure (which stays NOT a finding for the plate itself — [[feedback_device_root_never_salted]]).
**How to apply:** build in the docs' order (lift attest path into fgtw first); the open decisions in docs/one-identity.md are Nick's. Related: [[project_android_widevine_plate]], [[project_linux_tpm_plate]], [[project_session_registers]], [[project_security_audit]].

**Plate and papers (Nick 2026-11-08, later the same day):** "leave the plate on each one, the best we can, then put the cert in the glovebox." Plate = public name (best per platform). Papers = non-exportable key in StrongBox / TPM / Secure Enclave, registered in the chain; a factory reset destroys them and leaves the plate claimed by the owner, so the device joins no other fleet and comes back only by the owner's tap (sibling or tag), which mints new papers. Green on the device in hand becomes proof (a cloned key can no longer light a clone), so the typed words can retire from the network path. Contention (more than one request for the identity in the window) shuts the network path for that add and requires BLE/NFC proximity, stays shut until the add finishes, and tells the owner someone else holds the handle. Also: tag enrolled as owner credential (one-device owners), title transfer to release a plate on sale. DECIDED 2026-11-08: papers overrule the no-keystore rule ("I think we have to overrule for papers"; the rule still holds for the plate and anything copyable). OPEN (Nick's): papers feeding device_secret (a v0 move), Android uninstall kills keystore keys (reinstall needs a tap), desktop papers = TPM HMAC over machine-id so they die on OS reinstall. All in docs/one-identity.md "Plate and papers".

**THE WHY (Nick 2026-11-08: "You're tracking why tho, right?"):** a device key must be STABLE (a reset device returns as itself, the fleet untouched) and SECRET (nothing else can become it). ferros has both — the kernel alone reads the hardware root (PIPE later answers without revealing it) — so a Pixel on ferros can be reset and reinstalled all day without touching the fleet. Hosted OSes give only one: stable sources (Widevine, machine-id, TPM, IOPlatformUUID) are readable or usable by any local code; secret sources (StrongBox, TPM-bound keys, Secure Enclave) die with a reset. Plate (stable, public, names) + papers (secret, mortal, proves) is the hosted-OS fallback, and the re-tap after a reset is the platform's cost, not the design's. ferros is the reference; the protocol treats papers and the ferros root as one thing (the device's key) differing only in assurance level; never import the plate/papers machinery into ferros.
