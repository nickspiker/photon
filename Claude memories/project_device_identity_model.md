Device identity for the TOKEN/FGTW stack lives in the **tohu** crate (renamed from passless-key; dir + package + repo `github.com/nickspiker/tohu`). It owns the per-platform device oracle producing `device_secret`, plus the frozen **v0** derivation (`handle_seed`, `vault_path_name`, `vault_anchor_key`). Oracle per platform: Linux `/etc/machine-id`, Windows `MachineGuid`, macOS `IOPlatformUUID`, Android `Settings.Secure.ANDROID_ID` read in-Rust via JNI (the app hands tohu the `JavaVM` at `JNI_OnLoad`; the Context is resolved via `ActivityThread.currentApplication()`, so **no Java change** — device-tested working on a Pixel, 16-byte ANDROID_ID). `device_secret = BLAKE3(oracle)`. Desktop derivation is byte-identical to the old photon `fingerprint.rs`, so existing desktop vaults are unaffected. See [[project_manifestus_custodes_split]] for the sibling crates.

Two honest, orthogonal user-facing axes (surfaced as bottom-strip pips on the Ready screen via `identity_posture()` in photon_app.rs): **Security** = resistance to theft/forgery (bounded by root strength: readable soft-ID → root-gated firmware → enclave → PIPE; everything today is a *readable* root = low). **Recovery** = resistance to permanent loss (single device → mirrored → anchored → vouching; Android ANDROID_ID is FDR-reset so single-device Android = low). Never collapse these into one score.

**OPTIONAL HARDENING (low priority — not urgent):** photon's FGTW device keypair is `derive(device_secret)` — *handle-independent*. A `device_secret` collision *would* be fatal there (two devices share a private key; the unlucky one can't get a distinct identity), BUT the collision is a non-issue at any realistic scale: ANDROID_ID is 64-bit, so the 50% birthday bound is ~5 billion installs (`1.177·2^32`) — more than every Android device on Earth, and Glyph/PIPE ships long before then; Photon isn't on iOS either. So this needs no action now. If ever revisited: bind the network/attestation key with the handle too (`device_secret` + `handle_seed`) so a collision is benign unless the *handle* also collides (which first-come claim forbids). Note: padding the oracle with model/make does NOT help — public facts add ~0 attacker-uncertainty and bring OTA-drift fragility ("Pixel 8 Pro"→"pro" re-rolls identity). The vault layer is already collision-safe (tohu folds `handle_seed` into vault paths/keys).

**Attest / narrow-waist split:** tohu has `attest_with(domain, message, device_secret)` (pure, no_std, snapshot-frozen) + `attest(domain, message)` (std, reads oracle) = `BLAKE3.derive_key("tohu-attest-<domain>-v0", message ‖ device_secret)`. tohu's ONLY job is "append the device secret" — content-agnostic, no signing, no new deps. The composite multi-egg **self-signing key** (Ed25519 + Dilithium + SPHINCS+ — "don't stand on one egg," mirrors CLUTCH defense-in-parallel) lives in **photon**, NOT tohu: photon signs its own binary and *mashes* its `app_signing_id` into the `message` it hands tohu. This copies ANDROID_ID's per-signing-key scoping done right (cross-platform, PQ, ferros-enforced not Google). `attest` is the ferros-syscall / PIPE seam: today in-process BLAKE3, later the kernel verifies photon's signature + appends the kernel-held secret, callers unchanged. DEFERRED (photon-side, ferros-gated): add the composite self-signing eggs + add SPHINCS+ dep; do the project signing-key ceremony deliberately (one-time); device_secret stays oracle-only so scoping switches on only when photon includes app_signing_id in the message — no forced break now.

**Sybil / PIPE framing:** model is **one owner per device** — the device is a physical-scarcity sybil-cost unit layered on `handle_proof`'s compute cost. ANDROID_ID is per-(device, user-profile, app-signing-key): sign the *whole stack* (Photon, Lumis, basecalc) with ONE key so they share `device_secret` per device (cross-app consistency); `app_id` in tohu still isolates each app's vault. This is **casual-sybil-proof** (a normal human can't mint many), but NOT against emulator/root farms. **PIPE in silicon** is the sybil-proof, collision-free, reset-surviving root — and the prerequisite for vouching that stakes real lives; the software oracle is an honest interim ("fun and games" until PIPE). Photon runs unprivileged, so Keystore/Play-Integrity attestation (Google-dependency, managed key) is rejected.
