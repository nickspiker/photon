Two first-paint bugs on the contacts (Ready) screen, both field reports from Nick 2026-10-01, both fixed in the desktop batch that day (unverified in the field).

**Orb — ROOT CAUSE and THE FIX (Nick 2026-10-01: "when we paint under we get a bool; if we never painted that pixel because something was there, skip the hitmap"):** pixels composite UNDER the chrome (flatten_chrome_into runs BEFORE content; the under-blend early-out `dst >= 0xFF000000` skips every pixel the chrome owns), but hit stamps were BLIND rect/circle fills done AFTER painting, so a Ready row scrolled under the title strip took the orb's pixels until a scroll dirtied the chrome. Two bandages were tried and REMOVED the same day: re-stamping the orb last every frame, then a geometric stamp floor (fluor content_top()). THE RULE NOW: a content hit stamp rides the paint decision — it runs BEFORE the content it is for paints, and writes only where `target[i] < 0xFF000000` (nothing opaque there yet; the bg is flattened last so unpainted pixels are transparent). photon: `stamp_hit_rect_under` / `stamp_hit_circle_under` (photon_app.rs) used by the Ready rows + avatar and the conversation message bands (stamped at `block_extra`, before the row's first paint; the msg_hit_rows table write keeps the same band test). fluor: `Button::draw_pill_immediate` stamps its bbox BEFORE its own paint, gated the same way (fluor working tree also carries unrelated uncommitted edits — not mine). Blind `restamp_hit_rect` stays ONLY for clears (HIT_NONE) and deliberate after-paint re-wins (plus button over the search box, wave buttons at frame end); the modal wave wipe is a direct `hit_test_map.fill(HIT_NONE)`. Screen swap also invalidate_chrome()s. The blind stamp_hit_circle is deleted (no caller). Cost: the hit map is a u16 plane; stamp passes are plain stores, a few percent of a frame — the double was structural, not hot.

**Two-row strip snap:** the filter strip's wrapped height is measured while drawn (flow.used, render.rs ~1886); v109 already starts rows at THIS frame's measurement, but the extent/clamp above use last frame's `ready_strip_h` (0 → one row on the first frame) and the correction frame was lost: `scene_dirty = true` at the measurement was overwritten by `scene_dirty = false` at the END of the same render_frame and nothing requested a redraw. FIX: the reset moved to the START of render_frame (a flag raised during the render survives to claim the next damage_rect) + ctx.window.request_redraw() beside the measurement. General lesson: a dirty flag raised inside render must not be cleared at the end of that render.
