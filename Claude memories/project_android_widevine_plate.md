Until PIPE, Android's root comes from the DMV (Nick 2026-11-02: "the plate numbers are going to come from the DMV, not me"). Widevine `MediaDrm.PROPERTY_DEVICE_UNIQUE_ID` is burned in at manufacture (Google-issued, which is fine), read locally from the TEE with no permission, no DRM session and no provisioning round trip (Google-in-the-loop would be the no-go). Nick's shape: `hash(serial ‖ photon signing cert)`; the BLAKE3 is the unchanged v0 derivation, the fingerprint is the concatenation.

CONVERSION BUILT 2026-11-02 (phase 2): photon `ui/photon_app/root_conversion.rs` (cfg android) + kete `FlatStorage::rehome_into` / `discard_device_vault` / `Rehomed`. KEY FACT: kete entry ADDRESSES never mix the secret in (derive_entry_key / derive_device_entry_key are app+key only); only the VALUE keys do, so a vault re-homes generically: live_addrs → read_stored → decrypt (device key, then identity key) → re-encrypt under the new secret at the SAME address, batched at 1<<24 bytes. Flow on the legacy device once the session is live (status tick, one-shot latch `root_conversion_started`): old signer sponsors the new key via make_bind_request + bind_device_held (idempotent) → rehome (failure discards the half-written new vault so the next start retries) → fgtw::protocol::depart_consent(old) + depart_device_consented(new) → discard the legacy vault files → process::exit(0); next start selects Widevine, user types the handle once (capsules die with the root). `Owed::Cleanup` (both vaults present at start, i.e. an interrupted move) re-binds idempotently, departs the old key and removes the old vault. Selection stays NEW FIRST (Nick: "always check the new format first"), so an interrupted re-home runs as the new device with a partial vault and the fleet refills.
