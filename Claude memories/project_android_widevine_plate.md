Until PIPE, Android's root comes from the DMV (Nick 2026-11-02: "the plate numbers are going to come from the DMV, not me"). Widevine `MediaDrm.PROPERTY_DEVICE_UNIQUE_ID` is burned in at manufacture (Google-issued, which is fine), read locally from the TEE with no permission, no DRM session and no provisioning round trip (Google-in-the-loop would be the no-go). Nick's shape: `hash(serial ‖ photon signing cert)`; the BLAKE3 is the unchanged v0 derivation, the fingerprint is the concatenation.

VERIFIED 2026-11-02 on the Pixel 8 Pro, airplane mode both times: `id 7907cc35 (32 bytes), level L1, cdm 19.5.0, plate 9f315c60` before AND after a factory reset, byte-identical. ANDROID_ID rotated with the wipe, so the phone became a new fleet device: Nick: "We just found the ira… if it rotates upon reset, that's not it."

BUILT 2026-11-02 (phase 1, v0.138.1 dev line): tohu `device::machine_fingerprint()` on Android = `widevine_root()` (ID ‖ cert) or legacy `android_id()` per `android_select_root()` (OnceLock, first call wins, required before any derivation; `android_root()` getter). kete `device_vault_present(app, secret)`. photon `select_android_root()` in jni_android.rs at the NetworkContext oracle site: new-root vault present or no vault → Widevine; only old-root vault present → legacy + "conversion owed" warn; Widevine unreadable → legacy (an error never flips a device onto a different root silently… it logs error). Posture: Android recovery pip 2 on the Widevine root. Logs carry blake3 prefixes only.

CONVERSION BUILT 2026-11-02 (phase 2): photon `ui/photon_app/root_conversion.rs` (cfg android) + kete `FlatStorage::rehome_into` / `discard_device_vault` / `Rehomed`. KEY FACT: kete entry ADDRESSES never mix the secret in (derive_entry_key / derive_device_entry_key are app+key only); only the VALUE keys do, so a vault re-homes generically: live_addrs → read_stored → decrypt (device key, then identity key) → re-encrypt under the new secret at the SAME address, batched at 1<<24 bytes. Flow on the legacy device once the session is live (status tick, one-shot latch `root_conversion_started`): old signer sponsors the new key via make_bind_request + bind_device_held (idempotent) → rehome (failure discards the half-written new vault so the next start retries) → fgtw::protocol::depart_consent(old) + depart_device_consented(new) → discard the legacy vault files → process::exit(0); next start selects Widevine, user types the handle once (capsules die with the root). `Owed::Cleanup` (both vaults present at start, i.e. an interrupted move) re-binds idempotently, departs the old key and removes the old vault. Selection stays NEW FIRST (Nick: "always check the new format first"), so an interrupted re-home runs as the new device with a partial vault and the fleet refills.

Test plan on the Pixel (Nick attests/pairs): pm clear → install the shipped v138 APK (holdmyoscilloscope.com/photon/v138/photon-messenger-android-release.apk, same signer) → attest + pair = legacy-root vault, device A in the fleet → install the dev build → start → "conversion owed" → session live → log lines `ROOT: moving … / vault carried … / device … left the fleet / moved; exiting` → reopen → `device root: Widevine` → attest → device B in the fleet, A gone, history intact. Identity succession (SuccessorRecord) is for whole-identity re-founding, not this.

DECIDED 2026-11-02 (option B, Nick: "likely fine, if they factory reset the phone the vault will need replicated and recrypted anyway"): PLATE AND KEY APART. Key root (`widevine_root()`, feeds device_secret) = Widevine ID ‖ signing cert ‖ ANDROID_ID: secret from other apps (ANDROID_ID is per signer) and rotates on a wipe, so a wiped phone pairs again from a sibling as before. Plate (`android_plate()`) = BLAKE3(Widevine ID ‖ cert): survives the wipe, names the phone. NEXT (not built): publish the plate in the device's fleet + phonebook records and a plate-refusal path (a wiped stolen phone comes back under a new key on a known plate → refuse/flag). Android recovery posture stays 1 pip. The conversion code is unchanged by this (it carries whatever `widevine_root()` returns).

PER-SIGNER SCOPING TESTED 2026-11-02: a throwaway-signed build (apksigner re-sign of the dev APK) read the SAME raw Widevine ID (hardware id prefix 7907cc35) while the plate (86136b2d vs 9f315c60) and ANDROID_ID (ba1be176 vs 7b11706f) differed. Android does NOT scope the Widevine ID per app on the Pixel 8 Pro: any app on the phone can read it, and the cert is public, so any app can compute Photon's device secret. That is desktop posture (machine-id is world-readable), one Security pip, a step down from ANDROID_ID's per-signer scoping, accepted as the price of surviving a factory reset (Nick: the DMV issues the plates). Fresh-install note: the service, and so the oracle, only starts after the POST_NOTIFICATIONS dialog is answered; `adb shell pm grant com.photon.messenger android.permission.POST_NOTIFICATIONS` skips it for tests.
